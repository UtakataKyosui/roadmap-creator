# フェーズ1の画面案（#35）

`ui-design.pen` の「Phase1 —」で始まるフレームと「Phase1 Task Card」コンポーネントが実装の正本。
白いカード、淡い背景（`bg-app`）、Noto Sans JP、indigoの主操作を使う。
色・角丸は `.pen` の変数と `src/styles/app.css` のトークンを同じ値で対応させる。
ステータスの色は未着手=グレー、進行中=indigo、レビュー=amber、完了=tealで全画面共通。

共通の枠は、上部バー（ロゴ、パンくず）と左サイドバー（Workspace・Project名、ロードマップ一覧、
表示中ロードマップのボード／タイムライン、プロジェクトのロードマップ）。
フェーズ1に存在しない画面（マイタスク、メンバー、設定、共有）への導線は置かない。

## ロードマップ一覧・作成（#17）

Workspace > Project のパンくずの下に名称リンクと名称編集ボタンを並べる。
下部に名称入力と「作成」。0件なら作成へ誘導する空状態を表示する。
作成後は新しいロードマップのボードを開く。編集は行内で保存・キャンセル。
空白だけ、契約の上限超過は入力に関連づけて表示する。失敗しても入力を保持する。

## ボード・タスク編集（#6・#12・#18）

未着手 → 進行中 → レビュー → 完了の4列。列名、件数、カード、追加ボタン。
カードのタイトルから詳細を開く。ハンドルでドラッグし、カード直前または列末尾へ移動する。
キーボード用にステータス選択と上下ボタンを提供する。

追加と詳細編集は同じ中央モーダル。タイトル、説明、担当者、開始日、期限、
ステータス、優先度、ラベル、キャンセル、保存。追加時は選んだ列、通常は未着手、優先度は中。
タイトルに初期フォーカスし、Tabをモーダル内に閉じ込め、Escapeで閉じ、起点へ戻す。
保存中は閉じる操作と重複送信を止める。監査情報は編集対象外。
409では入力を残し、最新の内容を読み込むボタンを表示する。
最新を読み込む操作では編集中の入力を置き換える旨を明示する。

## タイムライン（#8）

表示期間は28日。前へ・今日・次へを上部に置く。横方向と縦方向にスクロール可能。
左列はタスク名、右列は日付目盛と期間バー。バーと名前の両方から同じ詳細を開く。
開始・期限の両端を含める。同日は1日幅。期間外部分は切り詰め、完全に期間外なら明記する。
片方だけは指定日の1日マーカーと「開始日のみ／期限のみ」、両方なければ「日付未設定」。
初期版では日付のドラッグ変更を採用せず、詳細編集で変更する。

## 共通の状態

読み込み中、0件、取得失敗、権限なし、対象なしを区別する。
取得失敗は再試行、権限なし・対象なしは説明を表示する。
更新失敗は入力を保持する。ボード移動失敗は仮表示を戻し、理由・再試行を示す。
更新競合は自動で無言に上書きせず、再取得後に利用者が再操作する。
